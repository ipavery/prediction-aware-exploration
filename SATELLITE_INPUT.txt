SATELLITE FOOTPRINT CONDITIONING FOR LaMa

Base: ipavery/prediction-aware-exploration test-b,
c4f2062f5df66630cb9e85cff3d05d6fd02b6c24 (test satellite masks added).
This patch includes the satellite feature only. That base already includes the
earlier collection/initial-pair fix and scripts/generate_satellite_priors.py.

APPLY
Copy satellite_lama.patch into the repository root, then:
    git apply --check satellite_lama.patch
    git apply satellite_lama.patch
These commands do not switch branches or start/stop jobs. Review/check changes
before submitting another job. No production environment upgrades are required.

INPUT CONTRACT
Each split has global_gt/name.png, global_obs/name.png, and
global_satellite/name.png. Files are matched by name, not by independently
sorted positions. Images must have matching H/W and map coordinates.
GT and obs retain the existing encoding: 0=free, 255=occupied, 128=unknown obs.
Satellite: 0=outside building, 255=building extent. This is not occupancy.
Both outline and filled priors are accepted, but start with the filled prior.
The satellite is normalized to 0..1; unavailable/padded prior is 0.5 in memory.

Generate filled priors for BOTH your training and held-out validation data:
    python scripts/generate_satellite_priors.py --gt-dir "$DATA/train_3/global_gt"
    python scripts/generate_satellite_priors.py --gt-dir "$DATA/test/global_gt"
The generator refuses to overwrite existing output. Keep its existing output
if already generated, or choose a fresh --output-dir and use it as the split's
global_satellite directory. Inspect previews before a long training run.
The test split must contain held-out buildings, not copies of training pairs.

WHAT CHANGED AND WHY
lama/saicinpainting/map_pairs.py:
    Shared filename matching, loading, normalization, size validation, and
    prior-only random translation. No GT is used by deployment prior loading.
lama/saicinpainting/training/data/datasets.py:
    Adds use_satellite and satellite_shift_px. Shared crops/flips/padding apply
    to all images; the footprint uses nearest-neighbor mask transforms.
lama/saicinpainting/evaluation/data.py:
    Loads the same third file and preserves alignment during scaling/padding.
lama/saicinpainting/training/trainers/default.py:
    Optional fifth channel AFTER the original RGB+unknown-mask channels.
    Satellite is visible in unknown map regions. GT/output/losses stay RGB.
    Shared trainer resize/crop includes the footprint. Whole-prior dropout is
    training-only, independently sampled per example; dropped value is 0.5.
lama/saicinpainting/training/trainers/satellite_weights.py and lama/bin/train.py:
    Optional generator-only initialization from an existing LaMa checkpoint.
    Copies the old four input-channel weights and zero-initializes the fifth.
    Other tensor-shape mismatches fail explicitly. This is not optimizer resume;
    discriminator and optimizer start fresh. Ordinary checkpoint loading and
    the existing four-channel configuration are unchanged.
scripts/lama_pred_utils.py and scripts/explore.py:
    Add supplied real-run footprints to the inference batch and propagate them
    through primary and ensemble predictions. Legacy four-channel models ignore
    this extra batch field. No supplied footprint uses a neutral 0.5 prior.
lama/bin/predict.py and configs/prediction/map-satellite.yaml:
    Offline prediction with satellite checkpoints. The optional image refiner
    bypasses conditioning and is explicitly unsupported; keep refine=false.

NEW TRAINING CONFIGURATION
Use -cn big-lama-satellite. The original -cn big-lama remains four-channel.
New defaults:
    generator.input_nc=5, generator.output_nc=3
    training_model.condition_on_satellite=true
    training_model.satellite_dropout=0.2
    data.train.satellite_shift_px=2
    data.train.num_frames_to_skip=1 (one exported pair per map/run)
    data.batch_size=4; data.val_batch_size=1
The generator's existing offline shift/rotation/scale/boundary perturbations
are retained; the loader adds fresh +/-2-pixel translation per training access.
Set data.train.satellite_shift_px=0 to use only the saved perturbations.
Validation uses a deterministic center crop of 256x256 with no added jitter or
dropout. This is crop validation, not an exhaustive whole-building metric.
For separate full-map evaluation, use map-satellite prediction; large maps may
need additional memory. Choose data.train.out_size / val.out_size deliberately.

FIRST CHECK IN YOUR EXISTING pipe ENVIRONMENT
From the repository root:
    export PYTHONPATH="$PWD/lama${PYTHONPATH:+:$PYTHONPATH}"
    python -m unittest discover -s tests -p test_lama_satellite.py -v
From lama/, on an allocated compute node:
    python bin/smoke_satellite_inputs.py --data-dir "$DATA/train_3" \
        --checkpoint ../pretrained_models/weights/big_lama/models/best.ckpt \
        --device cuda:0
The smoke check builds the real LaMa generator, loads the adapted checkpoint,
reads one pair and footprint, and checks a forward pass and known-cell copying.
It does not train or write a model. CPU is also supported via --device cpu.

TRAIN
Example inside an allocated GPU job, from lama/:
    export PYTHONPATH="$PWD${PYTHONPATH:+:$PYTHONPATH}"
    export WANDB_MODE=offline
    export TORCH_HOME="$HOME/.cache/torch"
    DATA=/home/ipa28/nobackup/autodelete/lama_map_pairs
    OUT=/home/ipa28/nobackup/autodelete/lama_satellite_training
    mkdir -p "$OUT/experiments" "$OUT/tb_logs"
    python -u bin/train.py -cn big-lama-satellite \
        location=kth_train_3 \
        location.data_root_dir="$DATA" \
        location.out_root_dir="$OUT/experiments" \
        location.tb_dir="$OUT/tb_logs" \
        pretrained_generator_path=/home/ipa28/prediction-aware-exploration/pretrained_models/weights/big_lama/models/best.ckpt \
        trainer.kwargs.gpus=1 data.batch_size=2
Omit pretrained_generator_path to train from scratch. To smoke-test the training
loop first, append trainer.kwargs.max_epochs=1,
trainer.kwargs.limit_train_batches=1, +trainer.kwargs.limit_val_batches=1,
trainer.kwargs.num_sanity_val_steps=0, trainer.kwargs.val_check_interval=1,
and data.num_workers=0. Make sure the held-out split and its priors exist.

REAL-RUN INFERENCE
Use the NEW trained five-channel checkpoint; the old checkpoint has not learned
how to use satellite information. For exploration, point the existing model
configuration at the new trained run's config.yaml and models/best.ckpt.
Supply --satellite_dir /path/to/aligned_footprints, with one PNG named exactly
<map-folder-name>.png, or place satellite.png inside each map folder.
Those runtime names are map IDs, not collection timestamps. PNGs must already
match the UNPADDED, DOWNSAMPLED map grid. The loader adds the existing 500-pixel
mapping border with satellite value 0.5, then the shared model transform pads
both inputs identically. It never generates a deployment footprint from GT.
If a supplied directory is missing a map PNG or dimensions do not match, it
fails explicitly. With no footprint available, it announces neutral-prior use
for a conditioned model. This can be tested because training includes dropout.

Offline prediction, from lama/:
    python bin/predict.py --config-name map-satellite \
        'model.paths=[/absolute/path/to/trained/run]' \
        'model.display_names=[Satellite]' \
        indir="$DATA/test" outdir="$OUT/predictions"

VALIDATION SCOPE
Local CPU tests use real PyTorch/OpenCV/Albumentations for the modified data
and forward logic, a small convolution for channel/gradient checks, and real
checkpoint round-tripping. The full FFC/Lightning training stack and cluster
GPU execution are covered by the supplied smoke command, not by the local
unit tests. All production Python additions use Python 3.6-compatible syntax.
